# CLAUDE.md

Guidance for working in this repository.

## What this is

`loman` — a computation graph that tracks the state of each node and the
dependencies between them, so a change triggers a partial rather than a full
recalculation. Originally by Ed Parcell (see `AUTHORS`).

Under `src/loman/`:

- `computeengine.py` — the `Computation` object: the public API and the graph
  itself. This is the entry point, and the largest module by a distance.
- `nodekey.py`, `consts.py` — node identity, and the state enum values.
- `planning.py` — works out what needs recomputing after a change.
- `graph_utils.py`, `util.py` — graph traversal, the block-composition DSL
  (`FanIn`, `FanOut`, `RepeatedBlocks`…), and general helpers.
- `serialization/` — saving and loading. `computation.py` is the top level;
  `transformer.py` and `values.py` handle per-value encoding, `blobs.py` large
  payloads and the bring-your-own-store interface, `compression.py` the codec
  layer, `profile.py` and `default.py` which transformer applies where.
- `ui/` — the anywidget viewer: `builder.py`, `viewmodel.py`, `value.py`,
  `widget.py`, plus `static/widget.js` and `static/widget.css`.
- `compat.py`, `_extras.py`, `exception.py` — version compatibility, optional
  dependency resolution, and the exception hierarchy.

### Dependency facts that are load-bearing

All three are documented at length in `pyproject.toml`; the short forms:

- **`pandas >= 2.2` is a real floor, not caution.** Serialization records each
  datetime value's resolution via `Timestamp.unit` / `DatetimeIndex.unit` and
  restores it with `as_unit()`, which arrived with non-nanosecond support in
  pandas 2.0 — below it, a microsecond index is silently reread as nanoseconds,
  which is wrong timestamps rather than an import error. The floor is 2.2 rather
  than 2.0 because the format records a `DatetimeIndex`'s `freq` verbatim and
  pandas renamed the minute alias from `"T"` to `"min"` in 2.2.
- **`zstandard` is required, not optional.** Saving compresses by default, which
  is only a sensible default because zstd rejects incompressible data fast.
- **`pyarrow` is genuinely optional**, resolved by name through
  `loman._extras.require`, so there is no import statement for deptry to find.
  That is why `[tool.deptry.per_rule_ignores]` carries `DEP002 = ["pyarrow"]` —
  do not "fix" it by adding a top-level import. Follow the same pattern for
  anything new and optional.

## Ownership: locally owned vs Rhiza-managed

This repo syncs its development infrastructure from the
[`jebel-quant/rhiza`](https://github.com/jebel-quant/rhiza) template, currently
pinned at **`v1.7.3`** via `.rhiza/template.yml`, which selects the
`github-project` profile plus the `devcontainer` and `github-devcontainer`
templates.

**The authoritative, machine-generated list of synced files is the `files:`
block of `.rhiza/template.lock`.** It is regenerated by every sync. When in
doubt, consult it rather than this section — the list below is a readable
summary of it, and the lock file is what the tooling actually enforces.

### Locally owned — edit these freely

- `src/` — the library, including the shipped `ui/static/` assets
- `tests/` — the suite and its fixtures
- `pyproject.toml` — metadata, dependencies, and all tool configuration
- `README.md`, `CHANGELOG.md`, `AUTHORS`, `CLAUDE.md`, `mkdocs.yml`
- `LICENSE`, `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` — these are
  seeded by `/rhiza:init` but not synced, so they are yours to edit
- `docs/` — except `docs/index.md`, `docs/mkdocs-base.yml` and
  `docs/development/rhiza.md`, which are synced
- `local.mk` — this repo's own make targets (see below)
- `local-setup.sh`, `scripts/`, `bin/`
- `.github/workflows/compatibility.yml` — the only locally owned workflow
- `.rhiza/template.yml` — the pin and the profile selection

### Rhiza-managed — do NOT edit in place

These are overwritten by the next sync. To change one, open a PR against
`jebel-quant/rhiza`, or exclude the path in `.rhiza/template.yml`, then re-sync:

- `.github/workflows/rhiza_*.yml` — every CI/CD workflow except
  `compatibility.yml`
- `.github/` scaffolding — `dependabot.yml`, `release.yml`, `rulesets/`,
  `secret_scanning.yml`, `CONFIG.md`
- `Makefile` — a shim; see "The make layer is a shim" below
- `.pre-commit-config.yaml`, `ruff.toml`, `pytest.ini`, `.bandit`,
  `.editorconfig`, `.python-version`, `.gitignore`, `cliff.toml`
- `.devcontainer/`, `.rhiza/semgrep.yml`
- `docs/index.md`, `docs/mkdocs-base.yml`, `docs/development/rhiza.md`
- `tests/test_rhiza_packaging.py`

### Enforcing template ownership

The `check-managed-files` pre-commit hook refuses any commit that touches a path
in `.rhiza/template.lock`'s `files:` list. It reports only paths differing from
`HEAD`, so `make fmt` and CI stay green on a clean tree under `--all-files`.

**The sync itself is the one commit that must touch those paths**, so it needs
`SKIP=check-managed-files`. That ordering is not optional: adopting the hook
before the sync flow could skip it would make every subsequent
`/rhiza:update` unable to commit its own output. `.pre-commit-config.yaml`
points here for exactly this reason.

If a gate fails inside a Rhiza-owned file, the fix is upstream. Note it as such
rather than editing the file — the next sync would revert it anyway.

## Quality gates

Run gates as a bare `make <target>`, one at a time. Never invoke `.venv/bin/…`
directly: the thresholds, exclusions and arguments live in the task definition,
so a direct tool invocation measures something else and invents failures.

`make all` runs what CI runs: `fmt deps test docs-coverage security license
typecheck rhiza-test`. Individually, cheapest first:

| Target | What it does |
| --- | --- |
| `make fmt` | the pre-commit hooks (ruff, markdownlint, bandit, actionlint, interrogate, the rhiza checks) |
| `make typecheck` | `ty` over `src/` |
| `make docs-coverage` | interrogate, `--fail-under 100` over `src` **and** `tests` |
| `make deps` | deptry over `src` and `docs/notebooks` |
| `make security` | bandit over `src/` |
| `make rhiza-test` | the template's own checks, via the `pytest-rhiza` package |
| `make test` | the full suite with its coverage gate |

Also useful: `make complexity`, `make docs-examples`, `make semgrep`,
`make todos`, `make license`, `make test-lowest`, and the test extras
`make benchmark`, `make hypothesis-test`, `make stress`. `make help` lists
everything, with repo-owned targets in their own section at the end.

### The make layer is a shim

Rhiza 1.x replaced the make framework with the `rhiza-task` CLI. The synced
`Makefile` forwards every unmatched goal to it, so `make test` and
`uvx rhiza-task test` are the same gate, and `.rhiza/make.d/` no longer exists.

Two consequences worth knowing:

- **`make -n` cannot tell a real target from a typo**, because the catch-all
  pattern rule matches anything. `uvx rhiza-task list` is the authority on what
  exists.
- **`local.mk` is the seam.** `-include local.mk` is left open by the template,
  and an explicit rule beats the shim's pattern rule, so anything defined there
  wins over a forwarded task of the same name.

### Repo-owned targets in `local.mk`

- **`make install-graphviz`** — Loman shells out to Graphviz's `dot`, so the
  visualization and widget tests cannot run without it.
- **`make test-compat`** — runs the version-sensitive modules against the
  **oldest supported pandas** (`PANDAS_MIN`, an exact series glob rather than a
  lower bound — `>=2.0` resolves to the newest match and silently tests the same
  version twice). This is the gate behind the pandas floor above; `make test`
  does not cover it. CI runs it as `.github/workflows/compatibility.yml`.
- **`make bump` / `release` / `publish` / `rollback` / `release-status`** — the
  release flow, restored locally after rhiza 1.x dropped it in favour of a
  Claude Code skill. They drive a pinned `rhiza-tools`; the pin is deliberate,
  since 0.8.1 renamed a flag these targets pass.

## Conventions

- **Coverage**: `make test` enforces `--cov-fail-under=90`; actual coverage is
  far above it. Treat a new module with no tests as a defect regardless of what
  the gate says — the layout note below depends on that.
- **Docstrings**: `make docs-coverage` runs interrogate at `--fail-under 100`
  over `src` and `tests`, so every module, class and function needs one.
  `[tool.interrogate]` sets `ignore-overloaded-functions` (a `@overload` stub
  delegates its documentation to the implementation) and `ignore-nested-*`
  (test suites build graphs from inline node functions like
  `def b(a): return a + 1`, where a docstring would restate the body).
- **Comments explain why, not what.** The codebase is unusually heavily
  commented, and the comments carry decisions and their rationale — including
  the ones that were tried and rejected. Match that; a comment restating the
  code is noise, one recording why an obvious alternative is wrong is the point.
  Every broad `except Exception` carries its reason.
- **Bandit** skips `B301`, `B403` and `B404` — pickle and subprocess use is
  inherent to serialization here. Do not widen that list casually.
- **Markers**: `stress`, `property` and `kaleido` are declared in `pytest.ini`.
- **Commits** follow Conventional Commits with a scope, and `cliff.toml` parses
  them into the changelog. `CHANGELOG.md` is grouped by area and written for
  readers, not generated verbatim.
- **Errors**: exceptions derive from `ComputationError`, and the older
  `…Exception` aliases in `exception.py` are kept for compatibility. A failure
  that loses data silently should warn instead — see
  `UnserializableFunctionWarning`.

## Test layout

Tests live **flat under `tests/`, grouped by behaviour**, not mirroring
`src/loman/`. `[tool.check_test_layout]` sets `enforce = false` and records why:
`test_serialization.py` covers the whole `serialization/` package, and
`test_typing.py` exercises the annotated public surface, so it has no single
source counterpart. The parity that filename mirroring proxies for is enforced
directly by the coverage gate instead — **do not reshuffle the suite to mirror
the package.**

Groups worth knowing:

- `test_computeengine.py`, `test_planning.py`, `test_containers.py`,
  `test_nodekeys.py`, `test_consts.py`, `test_util.py`, `test_graph_utils.py` —
  the graph core.
- `test_serialization.py`, `test_serialization_behaviour.py`,
  `test_serialization_properties.py`, `test_compression.py`, `test_byos.py` —
  the save/load path, including hypothesis properties.
- `test_compat.py`, `test_pandas_compat.py`, `test_api_compat.py` — the
  compatibility surface, and what `make test-compat` runs against an older
  pandas. `test_api_compat.py` pins the public signatures.
- `test_ui_*.py`, `test_visualization.py` — the widget and rendering path.
- `test_docs.py` — executes the examples in `docs/`, so a stale example is a
  test failure rather than a surprise for a reader.
- `tests/benchmarks/`, `tests/stress/` — excluded from `make test`, run by
  `make benchmark` and `make stress`.
- `tests/fixtures/` — shared computation fixtures. `tests/perf.py` is a manual
  profiling helper, not a test module.
